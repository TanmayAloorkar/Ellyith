# Mod Panel, Purge and Styled Replies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a permanent button panel that mirrors every step-1a moderation command, a new `/purge` command, styled embed replies for every command, and the punishment-only case rule.

**Architecture:** Every command body moves into a "core" function that takes an `Invoker` (who, where, with which serenity context and data) and returns a styled `CreateEmbed`. Slash commands and panel handlers both build an `Invoker`, call the same core, and send the embed, so permissions, DMs, cases and logs cannot drift apart. Panel flows are stateless: all state travels in component `custom_id`s, decoded by one pure codec.

**Tech Stack:** Rust, poise 0.7.1, serenity 0.12.5, sqlx (PostgreSQL), chrono, tokio.

**Spec:** `docs/superpowers/specs/2026-11-22-mod-panel-design.md` (all sections). Mockups: `.superpowers/brainstorm/1226-1795342774/content/panel-v4.html` (panel, category replies, purge modal) and `styled-replies.html` (reply embeds). Step-1a spec `docs/superpowers/specs/2026-11-19-moderation-design.md` still applies.

## Global Constraints

- Same constraints as step 1a (`docs/superpowers/plans/2026-11-19-moderation-1a.md` Global Constraints): 512 MB host, bounded memory, runtime `sqlx::query` only, IDs as `BIGINT`, rustls only, secrets via env only.
- No new crates.
- Discord limits: ≤ 5 buttons per row, ≤ 5 rows per message, `custom_id` ≤ 100 chars, modal title ≤ 45 chars, ≤ 5 text inputs per modal, select ≤ 25 options, embed description ≤ 4096, field value ≤ 1024. Answer every interaction within 3 s (defer when the work can be slower).
- Command nesting is at most command > group > subcommand.
- Every reply (slash or panel) is an **ephemeral embed**, no allowed mentions, built by `src/reply.rs`. Colours: Members `#da373c`, Names & voice and Channels `#5865f2`, Records `#4e5058`, Config `#949ba4`, panel `#f0b232`.
- Cases only for: Warn, Timeout, Kick, Ban, Tempban, VoiceMute. Everything else that previously created a case posts a non-case entry to the `mod_actions` log instead.
- Panel actions authorise at the final step with the same rules as the slash command, before any DM or Discord action. Config panel actions run the explicit Manage Server / Administrator / owner check.
- No in-memory flow state.

## Review Focus

1. **A non-mod clicks a panel action** and submits the pop-up: refused with the slash command's message, before any DM, case or Discord action. Test: Task 6 (router authorises via the same core; unit test that every Action's core path calls `authorize` is impractical — instead Task 3's cores are the only entry points and Task 6's manual check covers a non-mod click).
2. **A stale, foreign or garbage `custom_id`** (old panel version, hand-crafted): answered "This panel is out of date — ask an admin to run /config panel again.", no panic, nothing done. Test: Task 5 `decode` returns `None` for junk; Task 6 router maps `None` to that reply.
3. **Purge amount edge cases**: `0`, `1001`, `15d`, `abc`, `-5`, `5x` rejected with a plain message; a member filter matching nothing deletes 0 and says so; messages older than 14 days and pinned messages are skipped and counted. Test: Task 4.
4. **Bot restarts mid-flow**: a pop-up opened before the restart still works after it. Test: Task 5 codec round-trips carry every needed value (no server state).
5. **Panel message deleted by hand**, then `/config panel` again: posts a new one without erroring on the missing old message. Test: Task 5 (missing old message ignored, DB updated).

### Task 4: Purge

**Files:**
- Create: `src/moderation/purge.rs`, `src/moderation/commands/purge.rs`
- Modify: `src/moderation/mod.rs`, `src/moderation/commands/mod.rs`, `src/lib.rs` (register `/purge`)

**Interfaces:**
- Consumes: Tasks 1, 3 (`Invoker`, `reply`), `crate::duration::parse_duration`, `logging::send_log`.
- Produces:
  - `pub enum PurgeAmount { Count(u32), Since(chrono::Duration) }`
  - `pub fn parse_amount(s: &str) -> Result<PurgeAmount, UserError>` — all digits → `Count` in 1..=1000 (else `UserError("Purge needs a number from 1 to 1000, or a time like 10m or 2h (up to 14 days).")`); otherwise `parse_duration`, must be ≤ 14 days (same error text).
  - `pub struct MsgInfo { pub id: u64, pub created: DateTime<Utc>, pub pinned: bool, pub author: u64 }`
  - `pub struct PurgePlan { pub delete: Vec<u64>, pub too_old: usize, pub pinned: usize }`
  - `pub fn plan(newest_first: &[MsgInfo], amount: &PurgeAmount, member: Option<u64>, now: DateTime<Utc>) -> PurgePlan` — candidates = messages matching `member` (if any); `Count(n)`: the first n candidates; `Since(d)`: candidates with `created > now - d`, at most 1000. Among candidates: pinned → `pinned += 1`; `now - created >= 14 days - 1 minute` → `too_old += 1`; else → `delete`.
  - `pub async fn run(inv: &Invoker<'_>, channel: ChannelId, amount: PurgeAmount, member: Option<UserId>, reason: Option<String>) -> Result<CreateEmbed, Error>` — authorise MANAGE_MESSAGES; bot needs Manage Messages + Read Message History in `channel` (check channel-level permissions from cache, else "I don't have permission to do that."); fetch history in pages of 100 (newest first) until the plan is satisfied, the window is passed, or 1000 messages scanned; delete in chunks of ≤ 100 (`delete_messages`), a chunk of 1 via `delete_message`; log to `mod_actions` with `action_embed`-style embed (moderator, channel, asked, deleted, skipped, member, reason); return `done(Tone::Channels, "🧹 Purged #<channel>", [("Deleted", n), ("Skipped", "x older than 14 days, y pinned") if any])`. No case, no DM.
  - `/purge amount:String channel:Option<GuildChannel (Text, News)> member:Option<User> reason:Option<String>`; channel defaults to the current one.

### Task 6: Panel router and the Members, Names & voice, Channels, Records flows

**Files:**
- Create: `src/panel/flows.rs`
- Modify: `src/panel/mod.rs` (`handle`), `src/events.rs` (`InteractionCreate` arm), `src/lib.rs` (`Data.home_guild`), `src/main.rs` (set it from `GUILD_ID`), `src/invoker.rs` (`from_interaction`)

**Interfaces:**
- Consumes: Tasks 1–5 (all cores, `purge::run`, `PanelId`, `view`).
- Produces:
  - `Data` gains `pub home_guild: GuildId`.
  - `Invoker::from_interaction(ctx, data, guild_id: GuildId, user: &User) -> Invoker`.
  - `pub async fn handle(ctx: &serenity::Context, data: &Data, interaction: &serenity::Interaction)` — only `Component` and `Modal` interactions whose `custom_id` starts with `mp:` and whose guild is `data.home_guild`; everything else is ignored. Undecodable `mp:` ids → ephemeral `refused("This panel is out of date — ask an admin to run /config panel again.", false)`. Errors from cores → `refused(<UserError text>, dm_skipped)` or the generic message (logged). Never propagates errors to the event handler.

Flow table (each step is the interaction response named):
| Click | Response |
|---|---|
| `Category(c)` on the public panel | new ephemeral message `view::category(c)` |
| `Home` / `Category(c)` inside an ephemeral reply | `UpdateMessage` to `view::home()` (ephemeral copy) / `view::category(c)` |
| `Action(a)` needing a member (all except Unban, Purge, CaseView/Reason/Remove, NoteView/Delete) | `UpdateMessage`: embed "<emoji> <label> — who?" + user select `PickUser(a)` + Back |
| `PickUser(Move)` | `UpdateMessage`: voice-channel select `PickChannel(Move, Some(user))` + Back |
| `Action(Purge)` | `UpdateMessage`: text/news channel select `PickChannel(Purge, None)` + Back |
| `PickUser(History | NoteList)` | defer ephemeral update, run core, show result embed (+ Back) |
